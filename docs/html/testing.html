Testing Strategy

How we test the backend, frontend, and shared packages — test pyramid, per-layer conventions, coverage thresholds, and how to run tests with Nx.

Testing Pyramid

(moderate, mocked repos)"] DOM["Domain Entity Tests
(many, fast, pure)"] FE["Frontend Component Tests

Ratio: ~70% domain / 20% application & frontend / 10% E2E. Most tests live where the logic is — pure domain entities and use cases.

Coverage Thresholds

Every project has coverageThreshold in its Jest config. These thresholds are enforced per-project.

Project Type Threshold Examples
Domain packages 80% (branches, functions, lines, statements) user-domain, order-domain, product-domain
Service apps 70% user-api-service, order-event-handler-service
Frontend apps 70% webapp, mobile
Shared packages 70% client-common

Backend Testing by Layer

Domain Layer (Highest Priority)

Pure unit tests with zero mocks and zero dependencies. Tests live co-located next to the source file: *.spec.ts.

What to Test Example
Entity create() and reconstitute() Defaults, required fields, generated IDs
Business methods user.activate(), product.discontinue()
State transitions PENDING → ACTIVE, ACTIVE → INACTIVE
Invariants & guards "Cannot activate without verified email"
Domain exceptions Throws typed errors, not generic Error 
// packages/user-domain/src/domain/entities/user.entity.spec.ts
describe('User Entity', () => {
  it('should create with PENDING status', () => {
    const user = User.create({ email: 'test@example.com', ... });
    expect(user.getUserStatus()).toBe(UserStatusEnum.PENDING);
  });

  it('should throw when activating without verified email', () => {
    const user = User.create({ ... });
    expect(() => user.activate()).toThrow(EmailNotVerifiedError);
  });
});

Use-Case Layer

Unit tests with mocked repository interfaces and mocked ACL validators.

What to Test Example
Orchestration logic Calls repository in correct order
Error propagation Domain error flows up unchanged
Event publishing eventPublisher.publish() called with correct payload
ACL validation Cross-service validator called before proceeding 
describe('CreateUserUseCase', () => {
  let useCase: CreateUserUseCase;
  let mockRepo: jest.Mocked<IUserRepository>;

  beforeEach(() => {
    mockRepo = { save: jest.fn(), findByEmail: jest.fn() } as any;
    useCase = new CreateUserUseCase(mockRepo);
  });

  it('should throw if email taken', async () => {
    mockRepo.findByEmail.mockResolvedValue(existingUser);
    await expect(useCase.execute(input)).rejects.toThrow(EmailAlreadyExistsError);
  });
});

Application Service Layer

Unit tests with mocked use cases and mocked IEventPublisher. Tests cursor routing (DynamoDB), DTO transformation, and event publishing orchestration.

Event Handler Service Layer

Unit tests for dispatcher logic (event type routing, Zod safeParse) and individual handler functions (delegation to use cases, idempotency guards for saga events).

Frontend Testing

Webapp (Next.js)

Component tests using Jest + React Testing Library. Tests live co-located: *.spec.tsx next to source file.

What to Test Example
Domain tables Rows render, badge variants correct, empty state shown
Action components Conditional buttons by entity status
Status-variant mapping Pure function returns correct badge variant per status 
// apps/webapp/src/components/users/users-table.spec.tsx
describe('UsersTable', () => {
  it('should render user rows', () => {
    render(<UsersTable users={mockUsers} />);
    expect(screen.getByText('john@example.com')).toBeInTheDocument();
  });

  it('should show empty state', () => {
    render(<UsersTable users={[]} />);
    expect(screen.getByText('No users found')).toBeInTheDocument();
  });
});

Mobile (Expo / React Native)

Component tests using Jest + React Native Testing Library. Tests live co-located: *.spec.tsx next to source file.

What to Test Example
Domain lists (FlatList) Items render, navigation on press, loading & empty states
Detail screens Conditional action buttons by status, mutation calls
Status-variant mapping Pure function returns correct badge variant per status

Shared Package Testing (@old-st/client-common)

The shared data-access layer has its own test suite covering API clients and React Query hooks.

What to Test How
API clients Mock globalThis.fetch, verify URL construction, HTTP method, body, and Zod schema parsing
React Query hooks renderHook() + QueryClientProvider wrapper, verify query keys, enabled flags, mutation calls
Error classes Verify ApiError shape matches backend error response
Config Verify configureApi() sets base URLs correctly

Running Tests

# Test a single project
pnpm nx test user-domain
pnpm nx test webapp
pnpm nx test mobile
pnpm nx test client-common

# Test all domain packages
pnpm nx run-many --target=test --projects=*-domain

# Test all service apps
pnpm nx run-many --target=test --projects=*-service

# Test everything
pnpm nx run-many --target=test

# With coverage report
pnpm nx test user-domain --coverage

# Watch mode (useful for TDD)
pnpm nx test user-domain --watch

# Run a specific test file
pnpm nx test user-domain --testPathPattern=user.entity

# Skip Nx cache for verification
pnpm nx test user-domain --skip-nx-cache

Test Best Practices

  • AAA pattern: Arrange, Act, Assert — every test follows this structure.
  • One assertion group per test: Each it() tests one behavior.
  • Descriptive names: "should throw when activating user without verified email"
  • Independent tests: No shared mutable state between tests. Use beforeEach to reset.
  • Test edge cases: Zero values, empty arrays, null/undefined inputs, boundary conditions.
  • Mock at boundaries: Mock repository interfaces, not internal methods.
  • No testing implementation details: Test behavior, not how the code works internally.
