Workflow Orchestrators

AI-guided multi-step workflows that interview you first, plan the work, execute each phase in order (loading the correct skills), and validate between steps. Orchestrators ensure nothing is missed when working across multiple architecture layers.

Overview

The template ships 40 individual skills (single-layer instructions) and 5 workflow orchestrator prompts (multi-layer workflows). Skills tell Claude Code how to build one thing correctly; orchestrators tell Claude Code what order to build things in and what to ask before starting.

Orchestrator prompts live in .claude/commands/ and are invoked as slash commands. You can also describe what you want in plain English — Claude Code will read the decision tree in CLAUDE.md §11.1 and propose the appropriate workflow.

How It Works

Every orchestrator follows a four-stage lifecycle:

Stage What happens Why it matters
Interview Claude Code asks structured questions about the domain, entity, persistence, endpoints, and frontend needs. Prevents assumptions. Ensures all required information is gathered before any code is written.
Plan Based on answers, the orchestrator determines which phases to execute and which skills to load. Skips inapplicable layers (e.g. no Prisma steps for a DynamoDB domain). Optimises the workflow for each specific request.
Execute Phases run sequentially. Each phase loads its skill(s), generates code, and runs a validation gate (get_errors). Inner layers are built before outer layers consume them. Errors are caught and fixed before they cascade.
Verify Final step: nx test + nx build for all affected projects. Guarantees the code compiles, tests pass, and the workspace is in a clean state.

Available Workflows

New Domain

.claude/commands/new-domain.md

Scaffold a complete new domain from scratch — domain package, contracts, microservice, and infrastructure. Orchestrates 8+ skills across 10 phases.

Trigger: “I want to add a new payments domain”

New Feature

.claude/commands/new-feature.md

Add a capability to an existing domain — endpoint, business rule, state transition, or query. Skips unchanged layers automatically.

Trigger: “Add a suspend feature to the user domain”

New Service

.claude/commands/new-service.md

Register a new NestJS microservice (HTTP API or SQS event handler) in the Nx workspace. Covers project scaffold, service layers, and infrastructure.

Trigger: “Create a notifications API service”

Full-Stack Feature

.claude/commands/full-stack-feature.md

Add a feature across backend, webapp, and mobile — the full vertical slice. Orchestrates 10+ skills from contracts to mobile components.

Trigger: “Add order discount support end-to-end”

Event Service

.claude/commands/new-event-service.md

Add event publishing, consuming, or a choreography saga. Detects the pattern (intra-domain, cross-domain, saga) from your description.

Trigger: “When a product is discontinued, cancel pending orders”

Skills vs Orchestrators

Individual Skill Workflow Orchestrator
Scope Single layer (e.g. “create a DynamoDB schema”) Multiple layers in sequence (e.g. “create an entire domain”)
Interview Minimal — asks only what that layer needs Comprehensive — gathers all information upfront
Validation None between phases (single phase) Validation gate after every phase
When to use Targeted changes to one layer Multi-layer changes where ordering and completeness matter
File location .claude/skills/{name}/SKILL.md .claude/commands/{name}.md

You do not need to choose between them — Claude Code activates the right one based on your request. A simple “add a Zod schema for orders” uses the add-contracts skill directly. A complex “scaffold a notifications domain end-to-end” activates the new-domain orchestrator.

Example Walkthrough: Adding a New Domain

Here is what happens when you say: “I want to add a new payments domain with Prisma persistence”

1. Interview

Claude Code asks 10 structured questions about the entity, fields, statuses, business rules, access patterns, endpoints, cross-service communication, and frontend visibility.

2. Phase 1 — Domain Package

Loads new-domain-package, new-domain-entity, and domain-business-rules skills. Creates packages/payment-domain/ with entity, constants, exceptions, use cases, repository interface. Runs get_errors — fixes any TypeScript issues.

3. Phase 2 — Persistence

Loads new-prisma-schema and prisma-repository skills. Creates the Prisma schema, generates the client, implements the repository. Validates.

4. Phase 3 — Contracts

Loads add-contracts and contracts-subpath-imports skills. Creates packages/contracts/payment/ with Zod schemas. Validates.

5. Phases 4–7 — Service + API + Infrastructure

Registers the Nx project, scaffolds NestJS layers, implements controller routes with Swagger, adds env vars, VS Code tasks, and database config. Validates after each phase.

6. Phase 8 — Tests

Writes and runs domain entity + use case tests. All must pass.

7. Final Verification

nx test payment-domain + nx build payment-api-service — zero errors.

Creating Custom Orchestrators

Teams cloning this template can add their own workflow orchestrators for project-specific patterns. Create a .md file in .claude/commands/ with this structure: 

---
description: "Trigger phrases for when this workflow should activate."
---

# Workflow Name — Guided Workflow

## Phase 0 — Interview
[Structured questions to collect before any code]

## Phase 1 — [Layer Name]
**Load skill:** `.claude/skills/{skill}/SKILL.md`
[What to create/modify]
**Validation gate:** Run `get_errors` on affected files.

## Phase N — ...

## Final Verification
[nx test + nx build commands]

The description field in the YAML frontmatter controls when the orchestrator activates. Include multiple trigger phrases separated by commas. Each phase should load specific skills, produce valid code, and validate before proceeding.
