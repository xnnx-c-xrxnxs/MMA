Notifications

How CloudWatch alarms reach the team. SNS topics, AWS Chatbot Slack channels, email subscribers, and how to add new channel types (PagerDuty, Opsgenie, Microsoft Teams).

Architecture

Every CloudWatch alarm publishes to a per-environment SNS topic created by infra/modules/notifications/. The topic fans out to all configured subscribers — adding a new email or Slack channel is a JSON-only change.

Configuration

All notification config lives in a single file: infra/notification-config.json. It is environment-aware — you can configure different channels per environment (e.g. only prod pages on-call). 

{
  "dev": {
    "emails": ["dev-team@example.com"],
    "slackChannels": []
  },
  "staging": {
    "emails": ["dev-team@example.com"],
    "slackChannels": [
      { "channelId": "C012345", "channelName": "alerts-staging" }
    ]
  },
  "prod": {
    "emails": ["dev-team@example.com", "ops@example.com"],
    "slackChannels": [
      { "channelId": "C067890", "channelName": "alerts-prod" }
    ]
  }
}

On the next terraform apply, the module:

  • Creates one SNS subscription per email — recipients get an SNS confirmation email they must click once.
  • Creates one AWS Chatbot Slack channel configuration per Slack channel — the channel must already exist in Slack and the workspace must have completed the AWS Chatbot OAuth handshake (one-time, per workspace).

First-Time Setup

Email subscriptions

Add the email to notification-config.json → run terraform apply → recipient receives "AWS Notification — Subscription Confirmation" email → click the confirmation link. Until confirmed, the email subscription is in PendingConfirmation state and receives no alerts.

Slack workspace (one-time per workspace)

Before the first Slack channel can be wired:

  1. Open the AWS Chatbot console (in the same AWS account that runs the monitoring tool).
  2. Click Configure new client → Slack.
  3. Authorise the AWS Chatbot Slack app for your workspace (one-time OAuth handshake).
  4. Copy the resulting Slack workspace ID.
  5. Set the workspace ID as the slack_workspace_id Terraform variable in each environment root that uses Slack notifications.

Per-channel setup

For each Slack channel:

  1. Create the channel in Slack (or pick an existing one).
  2. In Slack, invite the AWS Chatbot bot user to the channel.
  3. Copy the channel ID (Slack → channel name → View channel details → bottom of dialog).
  4. Add the entry to notification-config.json for the target environment.
  5. Run terraform apply.

Smoke Test

After applying, manually publish a test message to the SNS topic: 

aws sns publish \
  --topic-arn arn:aws:sns:eu-west-2:<account>:<project>-<env>-alerts \
  --subject "Smoke test" \
  --message "Notifications are working."

Confirm the message arrives in:

  • Each confirmed email inbox (within ~30 seconds)
  • Each configured Slack channel (via AWS Chatbot — formatted message)

Adding a New Channel Type

SNS supports a number of subscription protocols beyond email. Use the add-notifications skill (or /add-alerting prompt) to wire a new type. Common patterns:

ChannelSNS protocolRequired config
PagerDuty https PagerDuty SNS Events API integration URL
Opsgenie https Opsgenie SNS integration webhook URL
SMS sms Phone number (E.164 format)
HTTP webhook (custom) https Endpoint that returns 200 on the SNS subscription confirmation request
Microsoft Teams / Discord lambda Lambda relay (their webhook formats are not SNS-native)

For custom HTTPS endpoints (PagerDuty, Opsgenie, custom webhooks), SNS sends a one-time subscription confirmation HTTPS request — your endpoint must respond 200 OK to complete the handshake. Most third-party services handle this automatically when you use their official SNS integration URL.

Cost

  • SNS: $0.50 per million publishes; first 1,000 emails per month free, then $0.000002 each.
  • AWS Chatbot: Free.
  • Typical monthly cost: < $1 for a system with thousands of alarms per month.
