Webapp (Next.js Frontend)

How the Next.js App Router frontend is structured — from page orchestrators and domain components down to shared UI primitives, typed API clients, and React Query hooks. The webapp consumes backend microservices through a layered data-access architecture with Zod-validated responses.

Frontend Layer Architecture

The webapp follows layered separation similar to the backend's Clean Architecture. Each layer has a single responsibility and dependencies flow downward only.

Package Structure

The frontend is split across three packages with distinct responsibilities:

apps/webapp

Next.js App Router shell. Contains page orchestrators, domain-scoped components, layout (Sidebar, Header), status-variant mapping, and global styles.

packages/client-common

Framework-agnostic data access layer. Typed fetch-based API clients with Zod response parsing, React Query hooks (one file per domain), shared QueryClient config, and Providers bootstrap.

packages/ui

Shared UI primitives following the shadcn/ui pattern. Domain-agnostic components using class-variance-authority for type-safe variants and cn() for class merging.

Page Pattern — Thin Orchestrators

Every page follows the same pattern: it is a thin orchestrator that wires together React Query hooks, local UI state, and domain components. Pages never contain table markup, form logic, or direct API calls.

Anatomy of a Page

'use client';

export default function UsersPage() {
  // 1. Local UI state
  const [status, setStatus] = useState('ACTIVE');
  const [showCreate, setShowCreate] = useState(false);

  // 2. React Query hooks for data
  const { data, isLoading, error } = useUsersByStatus({ userStatus: status });

  // 3. Render: Header → Filters → Form toggle → Domain components
  return (
    <>
      <Header title="Users" />
      <Select value={status} onChange={setStatus}>...</Select>
      <Button onClick={() => setShowCreate(!showCreate)}>Create</Button>
      {showCreate && <CreateUserForm onClose={() => setShowCreate(false)} />}
      {isLoading ? <p>Loading...</p> : <UsersTable users={data.data} />}
    </>
  );
}

Base API Client

The apiRequest<T> function is the single point through which all HTTP calls flow. It wraps fetch, builds URLs with query parameters, and validates responses with Zod.

Function Returns Use Case
apiRequest<T>(baseUrl, path, options) Promise<T> All requests that return a body — passes schema option for Zod validation
apiRequestVoid(baseUrl, path, options) Promise<void> DELETE operations and other 204 responses
Every API client method must pass a schema option. This ensures all responses are validated at runtime, catching shape mismatches between frontend expectations and backend changes immediately.

Error Handling

Non-OK responses throw an ApiError that mirrors the backend's standardized error shape: 

class ApiError extends Error {
  readonly statusCode: number;    // HTTP status code
  readonly error: string;         // Exception class name from backend
  readonly message: string;       // Human-readable message

  get isNotFound(): boolean;      // statusCode === 404
  get isConflict(): boolean;      // statusCode === 409
  get isValidationError(): boolean; // statusCode === 400
  get isServerError(): boolean;   // statusCode >= 500
}

URL Configuration

API base URLs are configured once at app startup via a framework-agnostic singleton: 

// packages/client-common/src/infrastructure/config.ts
configureApi({
  userApiUrl:    'http://localhost:3000/api',
  productApiUrl: 'http://localhost:3001/api',
  orderApiUrl:   'http://localhost:3002/api',
});

// Every API client method calls getApiConfig() internally
const config = getApiConfig();
return apiRequest(config.userApiUrl, '/users', { schema });

In production, URLs come from NEXT_PUBLIC_API_{DOMAIN}_URL environment variables, passed from layout.tsx (Server Component) into the <Providers> client component.

React Query Hooks

One file per domain (use-users.ts, use-products.ts, use-orders.ts) exports query and mutation hooks. All 41 hooks are re-exported from a single barrel (hooks/index.ts).

Query Key Convention

// Base key per domain — used for broad invalidation
const USERS_KEY = 'users';
const PRODUCTS_KEY = 'products';
const ORDERS_KEY = 'orders';

// Specific keys
queryKey: [USERS_KEY, userId]                    // Single entity
queryKey: [USERS_KEY, 'by-status', { status }]   // Filtered list
queryKey: [ORDERS_KEY, 'by-customer', { customerId, page, limit }]

Cache Invalidation Strategy

Mutation Type Invalidation Pattern Example
Create / Delete Invalidate all domain queries (broad) invalidateQueries({ queryKey: [USERS_KEY] })
State change (activate, deactivate) Invalidate entity + filtered lists [USERS_KEY, userId] + [USERS_KEY, 'by-status']
Field update Invalidate entity + relevant list [USERS_KEY, userId] + [USERS_KEY, 'by-role-and-status']

QueryClient Config

// packages/client-common/src/lib/query-client.ts
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 30_000,           // 30 seconds before refetch
      retry: 1,                    // Retry once on failure
      refetchOnWindowFocus: false,  // Don't refetch on tab switch
    },
  },
});

The getQueryClient() function returns a singleton on the browser and a fresh client per SSR request on the server — preventing cross-request cache pollution.

How Contracts Are Consumed

The webapp uses the same @mma/contracts package as the backend, imported via domain-scoped subpaths:

Usage Import From Example
Response validation (API client) @mma/contracts/{domain} userResponseSchema passed to apiRequest({ schema })
Input types (forms) @mma/contracts/{domain} CreateUserInput used for form state typing
Status enums (actions, badges) @mma/contracts/{domain} UserStatusEnum.ACTIVE for conditional rendering
Status arrays (filter dropdowns) @mma/contracts/{domain} USER_STATUSES to populate <Select> options
Pagination wrappers @mma/contracts/common paginatedResponseSchema(), offsetPaginatedResponseSchema()
Never import from the bare @mma/contracts root — always use domain-scoped subpath imports (@mma/contracts/user, @mma/contracts/order, etc.). The root barrel creates transitive type coupling between all domains.
