Mobile (Expo / React Native)

How the Expo mobile app is structured — from screen orchestrators and domain components down to shared mobile-ui primitives, Expo Router file-based navigation, and the same React Query hooks and API clients shared with the webapp.

Mobile Layer Architecture

The mobile app follows the same layered separation as the webapp. The data-access layer (@old-st/client-common) is shared — hooks and API clients are written once.

Shared Data Access (@old-st/client-common)

The mobile app shares the exact same hooks and API clients as the webapp. This is the key architectural decision — write data-access code once, consume it in both web and mobile.

Status Badge Mapping

Status-to-badge-variant mapping in mobile uses domain constants from @old-st/contracts/{domain} — never hardcoded strings. 

// apps/mobile/src/lib/status-variants.ts
import { UserStatusEnum } from '@old-st/contracts/user';
import { BadgeVariant } from '@old-st/mobile-ui';

export const userStatusVariant: Record<string, BadgeVariant> = {
  [UserStatusEnum.ACTIVE]:   'success',
  [UserStatusEnum.PENDING]:  'warning',
  [UserStatusEnum.INACTIVE]: 'secondary',
  [UserStatusEnum.DELETED]:  'destructive',
};

Component Conventions

  • Domain-scoped folders: apps/mobile/src/components/{domain}/
  • All components use @old-st/mobile-ui primitives — never raw View/Text for interactive or styled elements.
  • Lists use FlatList (never ScrollView + map()).
  • Styles use StyleSheet.create() at the bottom of the file.
  • Screens are thin orchestrators — they wire hooks and components, nothing more.

API Configuration

The root layout calls configureApi() from @old-st/client-common with EXPO_PUBLIC_API_*_URL environment variables: 

// apps/mobile/src/app/_layout.tsx
import { configureApi } from '@old-st/client-common/infrastructure';

configureApi({
  userApiUrl:    process.env.EXPO_PUBLIC_API_USER_URL,
  productApiUrl: process.env.EXPO_PUBLIC_API_PRODUCT_URL,
  orderApiUrl:   process.env.EXPO_PUBLIC_API_ORDER_URL,
});
