# Scaffolding a New Domain Package

Every new domain package must mirror the structure described below.

## Required Information — Ask Before Starting

Before generating any files, confirm all of the following with the developer:

1. **Domain name** — the singular lowercase name (e.g. `order`, `product`, `payment`)
2. **Entity fields** — all attributes the entity holds, their types, and which are required vs optional
3. **Domain constants** — any enums the entity needs (e.g. statuses, roles, types)
4. **Access patterns** — how the entity will be queried (by ID, by status, by owner+status, etc.) — these drive GSI design
5. **Business rules** — see the `domain-business-rules` skill for the full elicitation checklist
6. **Persistence layer** — **DynamoDB OneTable** or **Prisma + PostgreSQL**? This choice affects steps 1, 7, and 9.

Do not proceed until all six are answered.

### Persistence Layer Decision

| Consideration | DynamoDB OneTable | Prisma + PostgreSQL |
|---|---|---|
| Pagination style | Cursor-based (`IPaginatedResponse`) | Offset-based (`IOffsetPaginatedResponse`) |
| ID generation | ULID (application-level) | UUID (database `@default(uuid())`) |
| Relational queries | Manual GSI design + single-table pattern | Native relations + `include` |
| Aggregate loading | Multi-model partition query | Single query with `include` |
| Local infra | LocalStack DynamoDB | Docker PostgreSQL |

## Directory Structure to Create

```
packages/{domain}-domain/
  package.json
  tsconfig.json
  jest.config.ts
  src/
    index.ts                          ← public barrel (domain + application exports)
    domain/
      index.ts
      constants/
        index.ts
        {domain}-statuses.ts          ← if entity has statuses
        {domain}-roles.ts             ← if entity has roles/types
      entities/
        index.ts
        {entity}.entity.ts
        {entity}.entity.spec.ts
      exceptions/
        index.ts
        {exception-name}.error.ts     ← one file per domain exception
    application/
      index.ts
      interfaces/
        index.ts
        {entity}-repository.interface.ts
      use-cases/
        index.ts
        create-{entity}/
          create-{entity}.use-case.ts
          create-{entity}.use-case.spec.ts
        get-{entity}-by-id/
          get-{entity}-by-id.use-case.ts
        ... (one folder per use case)
      exceptions/
        index.ts
        {entity}-not-found.error.ts
        invalid-input.error.ts
        ... (one file per application exception)
    infrastructure/
      index.ts
      schemas/
        {Entity}Schema.ts
      # ── DynamoDB persistence ──
      schemas/
        {Entity}Schema.ts
      repositories/
        index.ts
        dynamo-{entity}.repository.ts

      # ── OR Prisma persistence ──
      prisma/
        schema.prisma
      generated/                           ← auto-generated by prisma generate (gitignored)
        client/
      repositories/
        index.ts
        prisma-{entity}.repository.ts
```

## Step 1 — `package.json`

### DynamoDB persistence
```json
{
  "name": "@old-st/{domain}-domain",
  "version": "0.0.1",
  "private": true,
  "main": "./src/index.ts",
  "dependencies": {
    "@old-st/common": "*",
    "@old-st/dynamodb-onetable": "*",
    "dynamodb-onetable": "*"
  }
}
```

### Prisma persistence
```json
{
  "name": "@old-st/{domain}-domain",
  "version": "0.0.1",
  "private": true,
  "main": "./src/index.ts",
  "dependencies": {
    "@old-st/common": "workspace:*"
  }
}
```

> Prisma domains do not list `@prisma/client` in the domain package — it is a root workspace dependency. The generated client lives at `src/infrastructure/generated/client/`.

## Step 2 — `tsconfig.json`

Use the same shape as any other domain package's `tsconfig.json`. The minimal contents are:

```json
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "outDir": "./dist",
    "rootDir": "./src",
    "types": ["node", "jest"]
  },
  "include": ["src/**/*.ts"],
  "exclude": ["node_modules", "dist", "**/*.spec.ts"]
}
```

---

## Step 2b — `jest.config.ts`

> **Nx project registration note:** Domain packages do **not** need a `project.json`. Nx auto-discovers them via the `@nx/jest/plugin` plugin declared in `nx.json`, which scans for `jest.config.*` files across the workspace. The `pnpm-workspace.yaml` (`packages/*`) handles package resolution. This `jest.config.ts` file is what makes `npx nx test {domain}-domain` work — do not skip it, and do not create a `project.json` for domain packages.

```typescript
import type { Config } from 'jest';

const config: Config = {
  displayName: '{domain}-domain',
  preset: '../../jest.preset.js',
  testEnvironment: 'node',
  transform: {
    '^.+\\.[tj]s$': ['ts-jest', {
      tsconfig: '<rootDir>/tsconfig.json',
      useESM: false,
    }],
  },
  moduleFileExtensions: ['ts', 'js', 'json'],
  coverageDirectory: '../../coverage/packages/{domain}-domain',
  testMatch: [
    '<rootDir>/src/**/*.spec.ts',
  ],
  testPathIgnorePatterns: [
    '/node_modules/',
    '\\.integration\\.spec\\.ts$',
  ],
  coverageThreshold: {
    global: {
      branches: 80,
      functions: 80,
      lines: 80,
      statements: 80,
    },
  },
};

export default config;
```

## Step 3 — Domain Constants

`src/domain/constants/{domain}-statuses.ts`:
```typescript
export const {ENTITY}_STATUSES = ['ACTIVE', 'INACTIVE', 'DELETED'] as const;
export type {Entity}Status = (typeof {ENTITY}_STATUSES)[number];

// Derive enum object from array — no duplication!
export const {Entity}StatusEnum = {ENTITY}_STATUSES.reduce(
  (acc, status) => ({ ...acc, [status]: status }),
  {} as Record<{Entity}Status, {Entity}Status>,
);
```

> **Do NOT use the TypeScript `enum` keyword.** Always derive the enum object from the `as const` array using `reduce`. This ensures the array (used for Zod validation in contracts) and the enum object are always in sync.

Use the developer's confirmed status/role values in place of the examples above.

## Step 4 — Domain Entity

See the `new-domain-entity` skill for structure.
See the `domain-business-rules` skill for encoding business logic.

> **Enum usage mandate:** Inside all entity methods, always use `{Entity}StatusEnum.ACTIVE`, `{Entity}StatusEnum.PENDING`, `{Entity}RoleEnum.ADMIN`, etc. for every comparison and assignment. **Never hardcode string literals** (`'ACTIVE'`, `'PENDING'`, etc.) in entity logic.

## Step 5 — Domain Exceptions

One file per exception in `src/domain/exceptions/`. Naming convention: `Cannot{Action}{Reason}Error` or `{Entity}Already{State}Error`.

```typescript
// src/domain/exceptions/cannot-delete-active-{entity}.error.ts
export class CannotDeleteActive{Entity}Error extends Error {
  constructor() {
    super('{Entity} must be deactivated before deletion');
    this.name = 'CannotDeleteActive{Entity}Error';
  }
}
```

Barrel `src/domain/exceptions/index.ts` must export every exception.

---

## Step 6 — Application Exceptions

`src/application/exceptions/`:
- `{entity}-not-found.error.ts` — thrown by get/update/delete use cases when entity does not exist
- `invalid-input.error.ts` — thrown for invalid input that cannot be validated at domain level
- Add others as needed per business requirement

```typescript
export class {Entity}NotFoundError extends Error {
  constructor(id: string) {
    super(`{Entity} with id ${id} not found`);
    this.name = '{Entity}NotFoundError';
  }
}
```

## Step 7 — Repository Interface

`src/application/interfaces/{entity}-repository.interface.ts`:

### DynamoDB persistence (cursor-based pagination)

```typescript
import { IPaginatedResponse } from '@old-st/common';
import { {Entity}Status } from '../../domain/constants';
import { {Entity} } from '../../domain/entities';

export abstract class I{Entity}Repository {
  abstract save(entity: {Entity}): Promise<{Entity}>;
  abstract findById(id: string): Promise<{Entity} | null>;
  abstract listByStatus(
    status: {Entity}Status,
    limit?: number,
    direction?: string,
    nextCursorPointer?: string,
    prevCursorPointer?: string
  ): Promise<IPaginatedResponse<{Entity}>>;
}
```

### Prisma persistence (offset-based pagination)

```typescript
import { IOffsetPaginatedResponse } from '@old-st/common';
import { {Entity}Status } from '../../domain/constants';
import { {Entity} } from '../../domain/entities';

export abstract class I{Entity}Repository {
  abstract save(entity: {Entity}): Promise<{Entity}>;
  abstract findById(id: string): Promise<{Entity} | null>;
  abstract findByStatus(
    status: {Entity}Status,
    page?: number,
    limit?: number
  ): Promise<IOffsetPaginatedResponse<{Entity}>>;
}
```

Only add methods for confirmed access patterns. Do not add speculative methods.

## Step 8 — Use Cases

See the `new-use-case` skill for each individual use case.

Minimum required use cases for any entity:
- `create-{entity}` — creates and persists
- `get-{entity}-by-id` — fetches or throws `{Entity}NotFoundError`
- `delete-{entity}` — soft or hard delete
- `update-{entity}-profile` — updates mutable fields

Add others based on confirmed business requirements.

---

## Step 9 — Schema + Repository (Persistence-Specific)

### DynamoDB OneTable path
- See `new-dynamo-schema` skill for the schema.
- See `dynamo-repository` skill for the repository implementation.
- Update `scripts/setup-localstack.ts` with the new table's GSI definitions.

### Prisma + PostgreSQL path
- See `new-prisma-schema` skill for the Prisma schema.
- See `prisma-repository` skill for the repository implementation.
- Add npm scripts for `prisma:{domain}:generate`, `prisma:{domain}:migrate:dev`, `prisma:{domain}:migrate:deploy`, `prisma:{domain}:studio` to root `package.json`.
- Register the domain in `scripts/prisma-migrate-all.ts` → `PRISMA_DOMAINS` array (so `DB: Migrate All` covers it).
- Add Docker Postgres database if not already present (see `docker-compose.yml`).
- Add `{DOMAIN}_DATABASE_URL` to `.env.local`.

---

## Step 10 — Public Barrel `src/index.ts`

Must export everything consumers need:
```typescript
// Domain layer
export * from './domain/constants';
export * from './domain/entities';
export * from './domain/exceptions';

// Application layer
export * from './application/interfaces';
export * from './application/use-cases';
export * from './application/exceptions';
```

The infrastructure layer (`src/infrastructure/index.ts`) is exported separately via the `@old-st/{domain}-domain/infrastructure` path alias. Do NOT re-export infrastructure from the main barrel.

---

## Step 11 — Register Path Alias in `tsconfig.base.json`

Add to `compilerOptions.paths`:
```json
"@old-st/{domain}-domain": ["packages/{domain}-domain/src/index.ts"],
"@old-st/{domain}-domain/infrastructure": ["packages/{domain}-domain/src/infrastructure/index.ts"]
```

## Final Checklist

- [ ] `package.json` with correct name and dependencies
- [ ] `tsconfig.json` extending root
- [ ] `jest.config.ts` with correct `displayName` and `coverageDirectory` (no `project.json` needed)
- [ ] Constants files with `as const` arrays and enum
- [ ] Entity with `create()` + `reconstitute()` factories
- [ ] Domain exceptions — one file each
- [ ] Application exceptions — one file each
- [ ] Repository interface as abstract class
- [ ] At least 4 use cases (create, getById, update, delete)
- [ ] **DynamoDB path:** DynamoDB schema with GSI for every access pattern + DynamoDB repository with `toDomain()` + `toPersistence()`
- [ ] **Prisma path:** Prisma schema with models, enums, indexes + Prisma repository with `toDomain()` + `$transaction` saves
- [ ] `src/index.ts` barrel (no infrastructure)
- [ ] `src/infrastructure/index.ts` barrel
- [ ] Path alias added to `tsconfig.base.json`
