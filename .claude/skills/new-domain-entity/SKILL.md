# Creating a Domain Entity

This skill covers **structure only**. For the business logic inside entity methods (invariants, state transitions, guards, exceptions) use the `domain-business-rules` skill.

---

## File Location

```
packages/{domain}-domain/src/domain/entities/{entity}.entity.ts
```

---

## Core Structural Rules

1. **Private constructor** — entities are never constructed with `new` directly by callers.
2. **Two static factory methods** — `create()` for new entities, `reconstitute()` for rehydrating from persistence.
3. **Private mutable fields** — all fields are `private`. Immutable fields use `private readonly`.
4. **Getter methods** — every field has a public getter. No public setters ever.
5. **Business methods are public** — methods that implement business logic (e.g. `activate()`, `verifyEmail()`) are public and mutate `private` fields directly.
6. **Zero framework dependencies** — no NestJS, no Zod, no DynamoDB imports. Pure TypeScript only.
7. **Zero repository calls** — entity methods never touch the database. Persistence is the use case's job.

## Template

```typescript
import { {ConstantType} } from '../constants';
import {
  {RelevantDomainExceptions},
} from '../exceptions';

export class {Entity} {
  private constructor(
    private readonly {entity}Id: string | null,  // null until persisted
    private field1: string,
    private field2: string,
    // immutable fields use readonly:
    private readonly dateCreated: string,
    private updatedAt: string,
  ) {}

  // ─────────────────────────────────────────────
  // Factory: Create a new entity (not yet persisted)
  // ─────────────────────────────────────────────
  static create(props: {
    field1: string;
    field2: string;
  }): {Entity} {
    // Field-level invariants go here — see domain-business-rules skill
    const now = new Date().toISOString();
    return new {Entity}(
      null,           // id generated by database (ulid)
      props.field1,
      props.field2,
      now,            // dateCreated
      now,            // updatedAt
    );
  }

  // ─────────────────────────────────────────────
  // Factory: Reconstitute from database record
  // ─────────────────────────────────────────────
  static reconstitute(props: {
    {entity}Id: string;
    field1: string;
    field2: string;
    dateCreated: string;
    updatedAt: string;
  }): {Entity} {
    // NO validation here — trust persisted data
    return new {Entity}(
      props.{entity}Id,
      props.field1,
      props.field2,
      props.dateCreated,
      props.updatedAt,
    );
  }

  // ─────────────────────────────────────────────
  // Getters
  // ─────────────────────────────────────────────
  get{Entity}Id(): string | null { return this.{entity}Id; }
  getField1(): string { return this.field1; }
  getField2(): string { return this.field2; }
  getDateCreated(): string { return this.dateCreated; }
  getUpdatedAt(): string { return this.updatedAt; }

  // ─────────────────────────────────────────────
  // Business methods go here
  // See domain-business-rules skill for how to implement these
  // ─────────────────────────────────────────────
}
```

## `create()` vs `reconstitute()` — Critical Differences

| Concern | `create()` | `reconstitute()` |
|---|---|---|
| Runs field-level validation | YES | NO |
| Sets default values | YES | NO — uses persisted values |
| Sets `id` to null | YES | NO — uses persisted id |
| Sets timestamps to `now` | YES | NO — uses persisted timestamps |
| Throws domain exceptions | YES | NO |

**Most common AI mistake:** running `create()` validators in `reconstitute()`. This breaks loading historical data that no longer passes current validation rules.

---

## Immutable vs Mutable Fields

| Field type | Declaration | Reason |
|---|---|---|
| Entity ID | `private readonly` | Set by DB, never changes |
| Creation timestamps | `private readonly` | Set once at creation |
| Email / owner identifier | `private readonly` | Business invariant |
| Status, role, profile fields | `private` (mutable) | Changed by business methods |
| `updatedAt` | `private` (mutable) | Updated on every mutation |

---

## Naming Conventions

- Entity class: `PascalCase` — e.g. `Order`, `Product`, `PaymentMethod`
- Getter: `get{FieldName}()` — e.g. `getOrderId()`, `getStatus()`
- Boolean getter: `is{State}()` — e.g. `isEmailVerified()`, `isDeleted()`
- Business method: verb — e.g. `activate()`, `verifyEmail()`, `updateProfile()`

## Aggregate Root Variant

When a domain entity **owns child entities** (e.g. Order owns OrderItem[] + OrderPayment), it becomes an Aggregate Root. The structural rules above still apply — the aggregate root adds composition, delegation, and cross-entity invariants.

### Additional Structural Rules for Aggregates

1. **Child entities are private fields** — stored as `private items: OrderItem[]` and `private payment: OrderPayment | null`.
2. **Collection getters return copies** — `getItems(): OrderItem[] { return [...this.items]; }` prevents external mutation.
3. **Mutation methods live on the root** — callers never modify child entities directly. The root orchestrates all changes (e.g. `addItem()`, `removeItem()`, `addPayment()`).
4. **Cross-entity invariants are the root's responsibility** — e.g. `payment.amount === totalAmount`, price drift check across all items before confirmation.
5. **`recalculateTotal()` is private** — called after every item mutation. Never exposed publicly.
6. **`reconstitute()` accepts pre-built child entities** — child entities are reconstituted by the repository, passed into the root's `reconstitute()`.

### Aggregate Root Template

```typescript
import { ChildEntity } from './child-entity.entity';

export class {AggregateRoot} {
  private constructor(
    private readonly {root}Id: string | null,
    private ownerId: string,
    private items: ChildEntity[],
    private payment: Payment | null,
    private status: Status,
    private totalAmount: number,
    private readonly dateCreated: string,
    private updatedAt: string,
  ) {}

  static create(props: { ownerId: string }): {AggregateRoot} {
    // Validate owner, set defaults, empty children
    const now = new Date().toISOString();
    return new {AggregateRoot}(null, props.ownerId, [], null, StatusEnum.DRAFT, 0, now, now);
  }

  static reconstitute(props: {
    {root}Id: string;
    ownerId: string;
    items: ChildEntity[];          // pre-reconstituted by repository
    payment: Payment | null;       // pre-reconstituted by repository
    status: Status;
    totalAmount: number;
    dateCreated: string;
    updatedAt: string;
  }): {AggregateRoot} {
    return new {AggregateRoot}(
      props.{root}Id, props.ownerId, props.items, props.payment,
      props.status, props.totalAmount, props.dateCreated, props.updatedAt,
    );
  }

  // ── Child mutation (always through the root) ──────────────────────────────
  addItem(item: ChildEntity): void {
    this.guardDraftOnly('add');
    this.items.push(item);
    this.recalculateTotal();
    this.updatedAt = new Date().toISOString();
  }

  removeItem(itemId: string): void {
    this.guardDraftOnly('remove');
    this.items = this.items.filter((i) => i.getItemId() !== itemId);
    this.recalculateTotal();
    this.updatedAt = new Date().toISOString();
  }

  // ── Cross-entity invariants ───────────────────────────────────────────────
  confirm(): void {
    if (this.items.length === 0) throw new CannotConfirmEmptyError();
    if (!this.payment) throw new PaymentRequiredError();
    if (this.payment.getAmount() !== this.totalAmount) throw new AmountMismatchError();
    // Check child-level invariants
    if (this.items.some((item) => item.hasPriceDrift())) throw new PriceDriftError();
    this.status = StatusEnum.CONFIRMED;
    this.updatedAt = new Date().toISOString();
  }

  // ── Collection getter returns defensive copy ──────────────────────────────
  getItems(): ChildEntity[] { return [...this.items]; }
  getPayment(): Payment | null { return this.payment; }

  private recalculateTotal(): void {
    this.totalAmount = this.items.reduce((sum, i) => sum + i.getSubtotal(), 0);
  }

  private guardDraftOnly(action: string): void {
    if (this.status !== StatusEnum.DRAFT) throw new CannotModifyError(action);
  }
}
```

### Child Entity Pattern

Child entities follow the same private-constructor + `create()` + `reconstitute()` pattern, but:
- Their ID is nullable (generated by DB, like the root).
- They typically have no status machine — business logic lives on the root.
- They may expose mutable methods called **only** by the root (e.g. `updateQuantity()`).
